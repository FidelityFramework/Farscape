# Library Verification & clefpak Architecture

## Overview

The Fidelity Framework uses **source-based linking** — no binary assemblies. Libraries are Clef source packages consumed by Composer's dependency walker. This requires a verification mechanism to ensure libraries are error-free before consumption.

## Verification Pipeline

```
C Headers → Farscape → Generated Clef Source + fidproj
                              ↓
                        farscape verify (CCS type-check, all modules reachable)
                              ↓ (pass)
                        clefpak pack (future — signed, compressed source artifact)
                              ↓
                        Package registry / dependency resolution
```

### The Reachability Trap

CCS performs reachability analysis on the PSG. Diagnostics on nodes not reachable from the entry point are demoted from `Error` → `Info` severity (`effectiveSeverity` in `Diagnostics.fs`). This means:
- A library with type errors **appears clean** as a dependency (nothing `open`s its modules)
- Errors only surface when application code reaches for those bindings
- Library verification must bypass this demotion to catch errors early

### `farscape verify` Command

```
farscape verify --fidproj <path-to-fidproj>
```

Invokes CCS against all library sources. Reports diagnostics at **true** severity (not demoted). Exit codes: 0=pass, 1=type errors, 2=infrastructure error.

### Feedback Loop

Verification failures are bugs in Farscape's generation pipeline (TypeMapper, WrapperCodeGenerator, etc.), not in C headers. Each fix addresses a class of C API patterns, maturing the generator systematically.

## fidproj Hierarchy

- Farscape generates **one fidproj per pilot TOML invocation**
- Library authors compose parent fidproj files at whatever hierarchical level makes sense
- Composer's SourceResolver walks dependency fidproj files recursively
- This is standard software library ecosystem practice — no one-size-fits-all

Example:
```
Fidelity.Platform/CPU/Linux/x86_64/
  Fidelity.Platform.fidproj           ← hand-authored parent
  Fidelity.Platform.libc.fidproj      ← generated by Farscape
  Fidelity.Platform.pthread.fidproj   ← generated by Farscape
```

## clefpak (Future)

Signed, compressed source artifact for the Fidelity package management system:
- Contains verified Clef source (not compiled binaries)
- Cryptographic signature for provenance
- Metadata: platform target, NTU version, dependency graph
- Verification is the prerequisite gate for packaging

## Farscape → Atelier Evolution

Farscape is an interim tool. Its capabilities evolve into Composer features accessible through Atelier IDE:

| Current (Farscape) | Future (Composer/Atelier) |
|---|---|
| C header parsing + binding generation | **Transpose**: Typed dynamic binding with full NTU/BAREWire integration |
| Layer 1 + Layer 2 + Overlay output | Integrated into Composer's binding pipeline |
| `farscape verify` | Composer library verification (built-in) |
| Pilot TOML project system | Composer project dependencies |

**Transcribe** (full algorithmic port from foreign source) extends beyond Farscape's scope — it handles source-to-source translation, not just FFI binding.
