# Native callback ABI gate

Run `python3 tests/native-callbacks/run.py` from the Farscape checkout. The gate builds the current Farscape CLI, regenerates bindings from the fixture pilot, and compiles and runs two fresh Linux x86-64 executables with the September numeric-model Composer. It requires Python 3, .NET, Clang for generation, and a C compiler (`cc` or `--cc`). No binary or log is written into the checkout; the printed temporary directory retains all evidence.

The default paths use sibling `Composer`, `Fidelity.Platform`, and `BAREWire` checkouts. Override them with `--composer`, `--platform`, and `--metadata`, or `COMPOSER_DLL`, `FIDELITY_PLATFORM_PROJECT`, and `BAREWIRE_METADATA_PROJECT`. The default platform is the accepted `Fidelity.Platform.CompilerSurface.fidproj`; `--platform` can select the WrenHello profile. `--generator` selects an existing Farscape CLI DLL instead of rebuilding. The March global `composer` tool is not used.

Each callback validates every argument. The C caller supplies a nonnull token, nonnull userdata, and unsigned 32-bit 4294967295; the callback reads both handles through generated declarations and returns signed -7, which C checks. The void callback validates both handles before recording 346, also checked by C. Retained MLIR must contain the declared 32-bit scalar entry and the separate native void thunk address. All native plumbing stays in the fixture's Boundary modules; application entry points call only the pure test wrapper.

The second executable regenerates the same C callback typedef names under another namespace and runs both sets together, checking record identity and descriptor resolution. The deterministic generated entry record names appear explicitly in `Boundary.clef`; a deliberate naming change requires updating this witness. This gate covers direct callbacks through the generated record, public wrapper, and private extern. GTK/WebKit UI behavior, teardown, and the accepted pthread migration have separate acceptance evidence.
